# Product Requirement Document (PRD)

**Project Name:** Internal Music Asset Dispatcher & Local Downloader Relay

**Document Version:** 1.0.0

**Target Platform:** macOS (Dedicated Node) + Cross-Platform Client Interfaces

**Primary Objective:** Eliminate manual relay overhead for team audio licensing by automating link ingestion, humanized native-browser execution, and shared cloud-drive directory syncing.

---

## 1. Executive Summary & Problem Statement

### 1.1 Context

The video editing team operates under a consolidated 5-member team subscription on Artlist. Downloads are currently centralized on a single dedicated workstation to streamline credential management.

### 1.2 Problem

The existing operational sequence introduces significant non-creative friction:

1. Video editor searches and finds a track on their personal workstation.
2. Editor physically walks over to the dedicated workstation (or requests manual access).
3. The track is manually downloaded on the dedicated machine.
4. The file is manually uploaded to Google Drive.
5. The editor returns to their workstation to sync/download the file into their local NLE (Premiere Pro / DaVinci Resolve).

### 1.3 Solution

Deploy an automated, local relay pipeline consisting of:

* A lightweight local queue ingest API (Flask / FastAPI) hosted on the dedicated Mac.
* An unpacked private Chrome Extension running in Manifest V3 to execute native, in-session DOM clicks with randomized jitter delays (0% bot-detection signature).
* Direct storage piping into the macOS Google Drive for Desktop virtual mount point for automatic sync back to editors' local machines.

## 2. Goals & Success Metrics

### 2.1 Primary Goals

* **Zero Walking Friction:** Reduce asset procurement round-trip latency from ~5–10 minutes to <45 seconds.
* **100% Account Safety:** Eliminate bot-detection risks by leveraging native browser runtime extensions rather than CDP debug bridges (`navigator.webdriver == false`).
* **Automated Asset Availability:** Files must automatically populate in editors' Google Drive local directories without manual file moving.

### 2.2 Key Performance Indicators (KPIs)

* **Download Success Rate:** $\ge 98\%$ on valid track URLs.
* **Peak Latency per Item:** Ingestion to Drive sync completion $\le 60\text{ seconds}$.
* **Daily Quota Management:** Hard-stop enforcement at 35 downloads/day to safeguard the 40-track daily account cap.

## 3. System Architecture & Technical Specifications

### 3.1 Component Overview

| Component | Technology | Responsibility |
| --- | --- | --- |
| **Client Ingestion** | HTTP REST / Webhook / Web UI | Accepts URLs from editors, validates format, submits to queue. |
| **Queue Manager** | Python (Flask / FastAPI) | Manages FIFO processing, prevents duplicate runs, tracks daily limits. |
| **Execution Engine** | Chrome Extension (Manifest V3) | Native DOM querying, simulated mouse delays, download triggering. |
| **Storage Pipeline** | Google Drive for Desktop (macOS) | Direct output sink for auto-syncing to all remote team members. |

---

### 3.2 Ingestion API Specification

* **Host:** Dedicated Mac (`0.0.0.0:5000`)
* **Endpoint:** `POST /api/v1/queue`

#### Request Payload

```json
{
  "url": "https://artlist.io/royalty-free-music/song/track-name/12345",
  "requested_by": "editor_1",
  "format": "WAV"
}

```

#### Response (Success: 200 OK)

```json
{
  "status": "queued",
  "queue_position": 1,
  "estimated_wait_seconds": 15,
  "daily_usage": "14/35"
}

```

#### Response (Rate Limit / Quota Exceeded: 429 Too Many Requests)

```json
{
  "status": "rejected",
  "error": "Daily safety quota reached (35/40). Manual download required."
}

```

### 3.3 Anti-Detection & Jitter Configuration

To completely mask automation patterns, the content script must enforce variable timing bounds:

```text
[Tab Created]
      │
      ▼ (Wait 3.5s – 6.5s: Page render & asset load)
[Simulated Scroll / Viewport Focus]
      │
      ▼ (Wait 1.2s – 2.4s: Human decision latency)
[Trigger Download Trigger Selector]
      │
      ▼ (Wait 0.8s – 1.6s: Menu popover transition)
[Select Lossless WAV Option]
      │
      ▼ (Wait 4.0s: File binary handoff to browser engine)
[Close Tab via runtime message]

```

* **Between Consecutive Queue Items:** Mandatory cooldown delay of $12\text{s} \text{ to } 25\text{s}$.

## 4. Functional Requirements

### 4.1 Queue & Quota Management

* **FR-1.1:** System MUST reject non-Artlist domain links.
* **FR-1.2:** System MUST maintain a daily counter reset at 00:00 local time.
* **FR-1.3:** System MUST prevent concurrent tab creation; downloads must be strictly serialized (FIFO) to avoid browser thread starvation and rate-limit triggers.

### 4.2 Extension & DOM Automation

* **FR-2.1:** Extension MUST operate silently in inactive background tabs (`active: false`).
* **FR-2.2:** Content script MUST handle dynamic single-page app (SPA) DOM state variations (handling both direct download icons and secondary modal dropdowns).
* **FR-2.3:** Background service worker MUST auto-terminate tabs after download handoff to prevent memory bloat.

### 4.3 Storage & File Ingestion

* **FR-3.1:** Google Chrome on dedicated node MUST have its default download directory set to the target Shared Drive path:
`/Users/<USERNAME>/Library/CloudStorage/GoogleDrive-<ACCOUNT>/Shared drives/<TEAM_FOLDER>/Artlist`
* **FR-3.2:** Browser MUST have *"Ask where to save each file before downloading"* explicitly toggled **OFF**.

---

## 5. Non-Functional & Security Requirements

* **Account Protection:** No direct automation frameworks (Selenium, Puppeteer, raw CDP ports) may be exposed externally. All browser tasks run under standard human extension permissions.
* **Resilience:** If a DOM selector fails or changes on Artlist's frontend, the extension must time out after 20 seconds, close the tab, log an error payload to the queue server, and notify the requesting editor.
* **Access Control:** The Flask queue service on the local network should restrict ingestion to local subnet IPs (`192.168.x.x` or `10.x.x.x`).

## 7. Operational Risks & Mitigation

| Risk | Likelihood | Impact | Mitigation Strategy |
| --- | --- | --- | --- |
| **Artlist Frontend Redesign** | Medium | Medium | Centralized selector dictionary in `content.js` allowing quick 2-minute updates if CSS classes change. |
| **Hit Daily 40-Song Cap** | Low | High | Enforce server-side software limit at 35 tracks/day. Hard alert to team lead when limit reaches 30. |
| **Mac Sleep / App Suspension** | Medium | Medium | Configure Mac Energy Saver settings to *"Prevent automatic sleeping when the display is off"* using `caffeinate` or Amphetamine. |
